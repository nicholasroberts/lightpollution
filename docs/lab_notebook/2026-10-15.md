## Frozen model sequence

```text
M0 controls only
M1 controls + snow + snow x baseline brightness
M2 controls + albedo + albedo x baseline brightness
M3 controls + snow + snow x baseline brightness

```

February is primary, January supportive and March negative control.

Primary endpoint: reduction in the snow-block partial R2 after albedo enters.
Main snow-coefficient attenuation is secondary because the snow x brightness
interaction means a single coefficient does not represent the whole snow
effect.

Both HC3 and country-clustered uncertainty are recorded for the combined model.

## Absolute versus relative outcome

Primary mechanism response:

```text
absolute anomaly =
R2021 - mean(R2020,R2022)
```

Context/sensitivity response:

```text
relative anomaly (%) =
100 x absolute anomaly / mean(R2020,R2022)
```

The stage writes a density-class summary and a paired absolute/relative figure.
This is required so the later long-term model is not judged only in percentage
space.

## Decision rule after the run

Strong support for the albedo pathway requires a positive February albedo-
radiance association, explanatory power beyond the validated snow model, and
material attenuation of the snow block. January should support the same
direction and March should remain materially weak/absent.

If this is supported, the next task is not another mechanism sweep. It is to
decide how the 2021 surface-reflectance disturbance should be controlled in the
historical series, refit the density-dependent response, and then regenerate the
historical validation in both percentage and absolute radiance units.

## First albedo run: CRS extraction bug caught before inference

The first full albedo run completed the expensive daily-to-monthly VNP43MA3
compositing and NUTS3 loop, but failed before plotting/inference with
`KeyError: 'month'` because the model table was empty.

Inspection showed the cause was spatial rather than statistical: AppEEARS
outputs were retained in native VIIRS/MODIS sinusoidal coordinates, while the
locked NUTS2016 polygons were still in EPSG:4326 when passed to
`exactextract`. The call returned rows but no usable physical overlap, so all
albedo eligibility tests failed and no models were created.

Fix committed before any albedo result was viewed:

```text
64ed94c  Fix VNP43MA3 zonal extraction CRS and cache invalidation
```

The fix:

- reprojects NUTS2016 polygons to each monthly composite raster CRS before
  extraction;
- uses ordinary coverage-weighted means in the native equal-area sinusoidal
  grid rather than spherical-area weighting on projected coordinates;
- versions the zonal cache so invalid pre-fix extractions cannot be reused;
- hard-stops immediately if a CRS-aligned extraction yields no physical WSA
  albedo / valid-area values;
- emits eligibility diagnostics if no models can be formed.

The already-built monthly composites remain valid and are cached, so the rerun
should reuse them and repeat only the zonal extraction and downstream analysis.

No scientific result from the failed run is retained.

## Historical snow acquisition automation

To test a general surface-state control without an ad-hoc 2021 correction, a
reproducible MOD10CM Collection 6.1 downloader was added.

Stage:

```bash
python src/run_pipeline.py future-radiance-download-snow-history
```

It uses NASA CMR discovery and Earthdata-authenticated direct downloads,
requests the complete monthly 2013-2024 archive, reuses the existing 2020-2022
files, resumes interrupted downloads, and records a manifest. The full monthly
archive is intentionally acquired now even though January-February is the
pre-specified first control window, because MOD10CM is compact and this avoids
further manual acquisition if seasonal sensitivity checks are needed.

No surface-state correction is applied by the download stage.

### MOD10CM archive-gap validation

The first automated CMR inventory check stopped before downloading because
February 2016 was absent. This is a genuine MOD10CM/Terra archive gap rather
than a downloader failure. NASA LDOPE records the Terra spacecraft entering
safe mode on 2016-02-18, with no instrument data for part of the outage and
degraded/unusable observations during recovery. The historical downloader now
permits two documented gaps within 2013-2024:

```text
2016-02
2022-10
```

The latter was already absent from the validated 2020-2022 archive and
coincides with the Terra constellation-exit outage. All other missing months
remain a hard failure.

### CMR S3-link downloader fix

The first authenticated historical MOD10CM download attempt failed because the
CMR granule record exposed an Earthdata Cloud `s3://` direct-access URL and
the downloader gave that link higher priority than the ordinary HTTPS
distribution link. Standard curl on EcoVis does not support the `s3://`
scheme.

Commit `479c1c2` changes discovery to use only HTTP/HTTPS HDF links. S3 links
remain visible in CMR metadata but are deliberately ignored by this downloader.
This keeps acquisition on the standard curl + Earthdata-authentication path and
does not add an AWS/S3 dependency.

### NSIDC Earthdata Cloud authentication fix

CMR HTTPS discovery succeeded, but direct MOD10CM download returned HTTP 401
when using a generic Earthdata bearer user token against
`data.nsidc.earthdatacloud.nasa.gov`. Current NSIDC command-line guidance for
this HTTPS endpoint uses the standard Earthdata Login `~/.netrc` plus cookie
jar workflow.

Commit `d532957` therefore changes the historical snow downloader to use the
documented NSIDC authentication path:

```text
~/.netrc
machine urs.earthdata.nasa.gov
login <EDL username>
password <EDL password>
```

with file mode 600 and a private `~/.urs_cookies` jar. Bearer-token-only
configuration now stops immediately with a clear message rather than issuing
repeated 401 requests.

### Switch MOD10CM transfer to earthaccess

The raw curl + `~/.netrc` route continued to return HTTP 401 from the NSIDC
Earthdata Cloud protected HTTPS endpoint despite matching the documented curl
syntax. Rather than continue reimplementing EDL redirect/OAuth behaviour, the
downloader now delegates authenticated transfer to NASA's supported
`earthaccess` Python client while retaining the existing CMR inventory,
checksum validation, file reuse, and manifest logic.

Commit `93df0db` makes this change and `earthaccess` is now an explicit
project requirement. Credentials remain in the user's private `~/.netrc`;
nothing is stored in Git.

## Historical winter surface-state test pre-registered

With the 2013-2024 MOD10CM archive complete, the next stage was frozen before
viewing its result.

```text
Stage: future-radiance-historical-snow-control
Annual panel: locked fixed NUTS2016, 2014-2024
Primary winter index: mean available Jan/Feb region-month snow anomaly
Sensitivity: require both Jan and Feb
Outcomes: log/% radiance and absolute nW radiance

```

February 2016 remains genuinely missing. The primary construction uses January
2016 only after converting it to a January-specific anomaly, avoiding a raw
one-month/two-month scale mismatch.

Decision to acquire full historical albedo is pre-registered: the snow block
must be significant at alpha 0.05 in at least one primary reporting space and
at least two density classes must change materially. Materiality thresholds
are 0.25 percentage points yr-1 in proportional space or 0.25% of class median
baseline radiance yr-1 in absolute space, with 25% relative-change and
non-trivial sign-change safeguards.
